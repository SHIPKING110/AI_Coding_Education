# ADR-0020：后台管理 / RAG 运营观测与指标口径

- 状态：已采纳
- 日期：2026-10-31
- 关联：ADR-0011、ADR-0013、ADR-0019、CONTEXT.md、docs/glossary.md

## 背景（Context）

当前“RAG 运营”模块混入了非 RAG 对话：Agent 工作台的寒暄、业务工具、Skill/MCP 任务也会生成检索 trace 或在总览里被计为 `zero`，导致：

1. 总览的命中率/零结果率被非 RAG 对话拉低，不能真实反映 RAG 知识库性能；
2. 任务型对话（如 PPT 生成）的详情只展示知识库命中，无法看到完整执行过程；
3. RAG 总览与其他 Tab 切换路径过长；
4. 缺少按会话维度的观测入口。

用户希望把模块改名为“后台管理”，并加入“会话观测”Tab，参考外部观测站的“会话 → 轮次 → 轮次详情”三级钻取。

## 决策（Decision）

### 1. 命名与导航

- 侧边栏与页面标题统一为“后台管理”；路由仍保持 `/rag/*`，避免大规模迁移。
- 所有后台页顶部使用统一二级 Tab 栏：总览 / 知识资产 / 检索追踪 / 任务监控 / 会话观测 / 路由测试 / 评测 / 设置。
- Tab 高亮当前路由，避免每次切 Tab 都回到总览。

### 2. RAG 指标口径（核心）

- **RAG 指标只统计实际触发 RAG 的检索**。非 RAG 对话（寒暄、工具、Skill/MCP、业务短路）不参与 RAG 命中率/零结果率，但进入意图统计与会话观测。
- RAG trace 状态从 `zero_result` 布尔值升级为 `rag_status`：
  - `hit`：最终有命中；
  - `no_hit`：触发检索但零命中；
  - `error`：检索异常/降级失败；
  - `skipped`：需要 RAG 但被跳过（无文档、短路等）；
  - `not_needed`：本轮未触发 RAG。
- 旧字段 `zero_result` / `is_error` 保留兼容，`rag_status` 由后端计算；历史数据回填为 `error ? error : zero ? no_hit : hit`。

### 3. 三层指标

1. **检索层**（RAG trace）：RAG 调用量、命中率、零命中率、错误率、向量/关键词/重排成功率、候选数、门控丢弃、Top1/平均相似度、阶段耗时 P50/P95。
2. **决策层**（Agent run）：意图分布、`needs_rag`、RAG 决策分布、漏检率（需要 RAG 但跳过）、跳过原因。
3. **端到端层**（run + trace + 反馈）：含 RAG 轮次成功率、用户反馈 up/down、首 token/总耗时、Token/成本、PPT 任务对齐率。

总览首页展示检索层 + 决策层摘要；详细页展开端到端与组件协同。

### 4. RAG 与工具/Skill/MCP 的边界

- RAG 指标只基于 RAG 调用本身，不混入工具结果。
- 另设组件协同指标：纯 RAG 轮次、纯工具轮次、RAG+工具同轮占比、RAG 仅辅助轮次、MCP/Skill 调用次数与成功率。
- 任务型指标（PPT）单独统计目标页数、当前页数、对齐率、产物链接，不与检索命中率混算。

### 5. 数据可靠性

- 默认 `trace_success_sample_rate = 1.0`（全量 RAG trace）；错误/零命中强制全量。
- 配置允许调低采样，但 UI 必须明确提示“采样 < 1 时命中率/零结果率仅作趋势参考”。
- RAG trace 继续异步落库、失败只记日志，不阻塞主链路。

### 6. 任务型对话详情

- 若 `task_kind` 非空或意图为任务型，详情主视图展示 Agent 执行时间线（spans：模型、工具、MCP、Skill、RAG、PPT 对齐）。
- 检索命中作为可折叠的“RAG 证据”区块，通过 `retrieval_trace_id` 关联。
- 纯知识问答仍以检索命中为主视图。

### 7. 会话观测

- 第一期只观测 Agent 工作台会话（`agent_conversations` + `agent_messages` + `agent_run_traces/spans`）。
- 家长客服会话作为第二期或单独 Tab。
- 三级钻取：
  1. 会话列表：聚合 run 数、消息数、意图、RAG 使用率、错误率、Token/成本、最近活跃；
  2. 会话详情：消息时间线 + 每轮 run 摘要；
  3. 轮次详情：run 基础信息 + spans 时间线 + RAG trace（如有）+ PPT 契约/产物。
- 需新增会话列表/详情 API，复用现有 run/span 详情接口。

### 8. 实施顺序

1. 文档与术语先行（本 ADR + glossary + CONTEXT）。
2. 后端：RAG trace `rag_status` 与派生指标字段、迁移/回填、会话聚合 API。
3. 前端：统一 Tab 栏、状态命名、任务型详情分流、会话观测页。
4. 指标与风险提示按新口径调整。

## 后果（Consequences）

- 正向：RAG 性能评估不再被非 RAG 对话稀释；任务型对话可追踪完整执行链路；Tab 切换成本降低；会话观测补齐生产排障入口。
- 代价：需要一次数据库迁移与历史回填；会话聚合查询需要谨慎分页与索引；高并发下全量 trace 可能增加存储压力，但默认采样率为 1.0 且错误/零命中强制保留。
- 边界：家长客服会话暂不纳入第一期；RAG 指标不直接评估最终回答质量，需结合反馈与端到端指标。
