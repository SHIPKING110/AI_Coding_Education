# ADR-0015：PPT 生成稳定性与工作区融合（续作意图/自动出片/产物隔离/预览融合）

- 状态：已采纳
- 日期：2026-10-23
- 关联：ADR-0013、ADR-0014、agent_tools.py、agent_planner.py、skill_exec.py、AgentsView.vue

## 背景（Context）

多轮对话后 PPT 生成暴露出三类问题：
1. 工作区「大纲」拥挤：预览与编辑割裂、已生成文案栏无用、页与成品对不上。
2. 多会话后 svg 与 pptx 风格/标题不一致；甚至下载到的是别的旧会话的 PPT，持续对话也调不回来。
3. 模型空口「我马上出片/继续」，却从不真正执行脚本 → 一直拖、拿不到文件。

## 决策（Decision）

### 1. 续作意图进 Skill 路径 + 自动出片兜底（问题3）
- 新增 `looks_like_ppt_continue`（出片/继续/下载/文件呢/生成好了吗…）：
  「催出片」这类短指令也进 Skill 路径，不再被门控挡在外面只剩空叙述。
- 新增 `auto_build_ppt`：当确属 PPT Skill 任务、模型读了文档/写了 SVG 却**始终没真正跑脚本**时，
  规划层末尾**替它对最近写过的项目跑一次 `ppt_oneshot.py build`**（时间窗 60 分钟内，防抓旧项目）。
  → 把「写好了页但没导出」的最后一步补上，杜绝「说了出片不出片」。

### 2. 产物按运行隔离（问题2 下载串味）
- `_collect_outputs` 改为写入 `_outputs/<run_ts>/`：每次运行的下载链接只指向**本次**产物，
  绝不覆盖/别名到历史运行的文件（此前同名覆盖 + 旧文件残留是「下载到旧会话 PPT」的直接诱因之一）。
- `auto_build_ppt` 只认 60 分钟内改过的项目，避免误抓其它会话遗留项目。

### 3. 工作区「大纲/预览」融合（问题1）
- 删除独立的「幻灯片预览」大块与「已生成文案」栏。
- 每行大纲标题可点击展开：**预览**（渲染真实生成的 SVG）+ **SVG 代码**（拉取源码查看）。
  数据来自最近一次助手消息里 `run_skill_script/write_skill_file` 产出的 `.svg` 文件（与成品一致），
  彻底消除「前端模拟 deckSlides vs 真实 pptx 两种风格」的割裂。

## 后果（Consequences）

- 正向：催出片能真出片；下载不再串旧会话；工作区一页一图，预览=成品。
- 代价/边界：
  - `projects/` 仍是「技能目录级」共享，不同会话用同一技能理论上仍可能看到彼此项目；
    本次用「时间窗 + 按运行隔离产物」缓解，**彻底隔离需把 projects 下沉到会话级**（后续可做）。
  - 预览依赖本次运行回收的 SVG 文件；若模型没写 SVG（只写 JSON），预览区会提示「本页暂无 SVG」。
