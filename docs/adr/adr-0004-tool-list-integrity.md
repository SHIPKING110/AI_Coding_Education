# ADR-0004：名单类工具的完整性与截断语义

- 状态：已采纳
- 日期：2026-06-16
- 关联：ADR-0001/0002/0003、`app/services/agent_tools.py`、`app/services/agent_planner.py`

## 背景（Context）

实测暴露两个问题：

1. **名单不完整**：教师问"这个班有哪些学员"，同名查询返回 20 个全机构学员（教师作用域缺失），
   且因结果超长，注入文本被**按字符数截断**——把一条记录（如演示学员06）从中间切开，
   模型据此渲染出"课时余额/状态 = 未返回"的半截行。
2. **无法判断"评估是否完成"**："XX班有哪些学员评估还没完成"——旧 `student_evaluations` 工具
   只返回**已存在的评估**，没写评估的学员压根不出现，模型分不清"已完成 / 未完成 / 未写"。

## 决策（Decision）

### 1. 教师作用域补齐（find_students / 按名查学员）

- `find_students`：教师只取"本人（在教）班级"中的学员，与前端学员管理的教师筛选同一套
  （`Student.classes.any(Class.teacher_id==user.id AND Class.status==active)`）。
- `_find_student_by_name`：同样加教师作用域，教师查不到非本人学员（进度/评估也随之受保护）。

### 2. 名单工具如实报告数量，不再静默截断

- `find_students` 返回 **总数 / 返回条数**，超过可见上限时返回"仅显示前 N 条，共 M 条"提示，
  由模型如实转述，绝不把残缺名单当完整名单。

### 3. 截断按"整条记录"而非"按字符"

`agent_planner.compact_result()`：当结果超长时，定位最大的数组字段（如 `学员`/`明细`），
**按整条裁剪**到预算内，并追加"另有 K 条未列出"。整块（`_format_block`）也按条裁剪。
放进最终 prompt 的永远是"完成的 N 条 + 明确提示"，不会出现半行、半条。

### 4. 新增 class_evaluation_overview 工具

"某班学员评估是否完成"用专门工具：**逐学员标注** 已完成 / 草稿·未完成 / 未写评估，
并给出班级完成数与未完成数。
- 已完成 = 有已发布(published)评估；
- 未完成 = 未写评估 或 评估仍为草稿(draft)。
规划器提示词同步引导（看到"评估没完成/还没写"就优先用该工具）。

## 理由（Rationale）

- 正确性优先：教师隔离避免张冠李戴；按整条截断避免模型幻觉出"未返回"的半截数据。
- 口径清晰：完成状态三态化，用户一眼知道是"没写"还是"没改完"。

## 后果（Consequences）

- 正向：名单完整、教师数据隔离、评估完成状态明确、超长结果不再产生半行。
- 代价：`compact_result` 对深层嵌套列表只处理最外层最大数组（当前工具均为"平铺 dict + 一个列表"，
  足够）；更深的嵌套需扩展裁剪算法（暂不需要）。
