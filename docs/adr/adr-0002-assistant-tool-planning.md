# ADR-0002：智能助手工具「规划层」——多轮 规划 → 执行 → 观察

- 状态：已采纳
- 日期：2026-06-16
- 关联：ADR-0001（业务工具层）、`app/services/agent_planner.py`、`app/services/agent_tools.py`

## 背景（Context）

ADR-0001 引入了只读业务工具，但采用的是「**规划一次 → 执行 → 注入**」的单轮模式：
一次 function-calling 选中若干工具，执行完直接把结果塞进回答 prompt。

当问题变复杂时这不够用：
- **需要串行依赖**：如"查一下小明最近的评估"，合理路径是「先按名字找到学员 → 再取其评估」；
  单轮拿到的是"要调哪些工具"的静态集合，无法根据中间结果决定下一步。
- **需要多工具**："这周考勤怎么样、顺便看看哪些学员课时不足、再给我教学数据" —— 一次要跑 3 个工具。
- **要求稳定**：多轮 + 模型不确定 ⇒ 必须防止无限循环、参数乱填、单点失败拖垮整轮。

用户明确要求一个**规划层**：理解问题、规划执行、高效、高质量、省 token、多轮且稳定。

## 决策（Decision）

新增规划层 `agent_planner.py`，实现**有界的 规划→执行→观察 循环（bounded tool loop）**：

1. **循环**：每轮用一次非流式 function-calling（`llm.tool_step`，温度 0）产出"下一步要调的工具有哪些"，
   执行后把结果作为观察（observation）追加回规划消息，进入下一轮，直到模型不再请求工具或触达预算。
2. **单轮可并行多工具**：一轮里的多个 tool_calls 一起执行（等价于并行），减少轮数 = 省往返。
3. **预算护栏**（可配置）：最大轮数 `AGENT_TOOL_MAX_ROUNDS`、最多工具数 `AGENT_TOOL_MAX_CALLS`、
   总时间预算 `AGENT_TOOL_TIME_BUDGET_MS`；任一触顶即收束。
4. **去重**：同一 (工具, 参数) 只执行一次，避免模型兜圈重复调用。
5. **省 token**：
   - 规划消息只带「系统角色 + 用户问题 + 各轮工具结果」，**不带对话历史**；
   - 工具结果回灌前截断（`AGENT_TOOL_RESULT_CHARS`）；
   - 注入最终回答的业务数据块限长（`AGENT_TOOL_BLOCK_CHARS`）；
   - 工具目录保持精简描述。
6. **稳定与降级**：每个工具单独 try/except（失败记为错误并继续）；规划调用异常时，
   若 LLM 不可用或首轮失败，**降级为关键词启发式单轮路由**（`agent_tools._heuristic_calls`）；
   任何情况下都返回结论，不向上抛异常。
7. **权限不变**：工具仍在服务端按 `user` 作用域取数，模型只决定"调哪个工具 / 传什么参数"。

对外唯一入口 `plan_and_run(db, user, message) -> PlanOutcome{steps, block, rounds, degraded}`。

## 理由（Rationale）

- **贴合现有流式架构**：规划在回答前完成（非流式），最终回答仍是原 SSE 流，前端协议零改动。
- **多轮但不失控**：预算护栏 + 去重 + 温度 0，让多轮在有界、确定、可复现的前提下运行。
- **省 token**：不叠历史上下文、结果截断、目录精简；大多数问题 1 轮即可（模型可一次给多个工具）。
- **高可用**：任一层失败都能降级到启发式或纯 RAG，用户始终能得到回答。
- **可扩展**：加一个业务能力 = 注册一个工具函数，规划层无需改动。

## 备选方案（Alternatives considered）

- **纯单轮规划（ADR-0001 现状）**：省一次往返，但无法处理串行依赖与"根据结果再决定"。改造为多轮。
- **全 ReAct（边想边调，无预算）**：灵活但延迟不可控、易死循环、token 不可控。否决为**无界**方案，
  只借鉴其"观察后继续"的思想并加以**有界化**。
- **并行工具调用 API 特性**：依赖具体模型是否支持一次返回多个 tool_calls；不支持时自动退化为逐轮。

## 后果（Consequences）

- 正向：智能助手能处理"多工具/带依赖"的问题，且稳定、省 token、易扩展、失败可降级。
- 代价：业务问题最多多出 `MAX_ROUNDS` 次非流式规划调用；通过预算是可控的（默认 ≤3 轮、≤6 工具、≤8s）。
- 后续：如需写操作（"帮我把某课排进课表"），将引入写工具 + 二次确认 + 审计，另立 ADR。
