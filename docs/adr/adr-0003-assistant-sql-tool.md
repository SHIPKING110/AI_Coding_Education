# ADR-0003：智能助手数据库查询工具 —— 只读 SQL + 多步取数

- 状态：已采纳
- 日期：2026-06-16
- 关联：ADR-0001（业务工具层）、ADR-0002（工具规划层）、`app/services/agent_sql.py`

## 背景（Context）

ADR-0001/0002 提供了「固定口径」的结构化工具（排课考勤、教学数据、班级、学员、评估）与多轮规划层。
但用户还会问**固定工具覆盖不到、需要临时统计**的问题，例如：
"各班级平均出勤率排名""本月课时消耗 top10 学员""按科目看报告产出趋势"。

这类问题需要**直接用 SQL 取数**，且天然是**多步**的：先看有哪些表 → 再看表结构 → 写 SQL → 执行 → 按报错修正。

风险：直接给模型执行 SQL 的能力，稍有不慎就会**写坏数据 / 越权读他人数据 / 拖垮数据库**。

## 决策（Decision）

新增**只读 SQL 工具**（`agent_sql.py`），注册进规划层（ADR-0002）供多轮调用：

1. **三个工具**（多步推理的三段式，与 LangChain `SQLDatabaseToolkit` 同构）：
   - `sql_list_tables`：列出可查表 + 用途；
   - `sql_describe_table`：看某表列/类型；
   - `sql_query`：执行单条只读 SELECT。
2. **只读护栏（多层防御）**：
   - **连接级只读**：专用引擎 `SET SESSION CHARACTERISTICS AS TRANSACTION READ ONLY`，物理上不允许写；
   - **语句级白名单**：仅允许 `SELECT` / `WITH`；单语句（禁止分号多语句）；关键字黑名单
     （insert/update/delete/drop/alter/... 及 pg_sleep、dblink 等危险函数）；
   - **列脱敏**：`password_hash`、`share_token`、`phone`、`ai_draft` 禁止查询；
   - **表白名单**：仅登记过的业务表，其余（系统表如 pg_shadow）直接拒绝。
3. **性能护栏**：强制 `LIMIT`（默认 50 行）+ `statement_timeout`（5s），避免全表扫描拖垮库。
4. **作用域（防越权）**：教师查询**含教师归属**的表（排课/班级/报告/评估/家长会PPT/反馈/学员/考勤/
   学员班级/课时流水/订单）时，**必须显式带上自己的 `teacher_id` 过滤**（或经 classes/student_classes 关联过滤），
   否则拒绝并提示。管理员/教务放开全局。
5. **首选用固定工具**：规划器提示词要求优先用 ADR-0001 的固定工具（快、口径统一），
   仅当覆盖不到时才走 SQL，避免"什么都用 SQL"带来的慢与不确定。

## 理由（Rationale）

- **安全第一**：只读事务 + 白名单 + 脱敏 + 作用域，多重防御使其即使被提示注入也写不了、越不了权。
- **多步推理**：复用 ADR-0002 的多轮循环，天然支持"看表→看结构→查询→纠错"。
- **不引重依赖**：用 SQLAlchemy 自实现（`langchain-community` 体积大、"科学上网"安装成本高），
  但保持与 LangChain SQL Toolkit **同构的工具形态**，未来可平滑替换。
- **省 token**：表目录保持精简；结果经规划层截断后再回灌。

## 备选方案（Alternatives considered）

- **`langchain_community.SQLDatabaseToolkit`**：现成但对"教师作用域"这种行级隔离控制弱，且依赖重。否决，自实现。
- **Postgres 行级安全（RLS）+ 会话 GUC**：最干净的作用域方案，但需要迁移建策略，成本高。列为后续演进。
- **不开放 SQL**：仅固定工具。覆盖不了临时统计需求，无法满足用户诉求。

## 后果（Consequences）

- 正向：智能助手可回答任意"临时统计/多步取数"类问题，且读写安全边界清晰。
- 代价：SQL 生成依赖模型能力；生成错误时靠"错误信息回灌 → 再修正"的多轮机制兜底。
- 已知局限：
  - 教师作用域是"必须带 teacher_id"的**字符串级校验**（防呆，非强隔离）；强隔离需 RLS/视图（后续）。
  - 枚举列在库中存**大写英文名**（如 `ATTENDED`/`COMPLETED`），已写入表目录提示，避免模型写小写。
- 后续：需要写操作时另立 ADR（写工具 + 二次确认 + 审计）。
