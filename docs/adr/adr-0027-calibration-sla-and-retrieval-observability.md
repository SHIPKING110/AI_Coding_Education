# ADR-0027：人工校准四指标 SLA + 检索观测/低置信门控/关键词腿与入库策略

- 状态：已采纳
- 日期：2026-11-13
- 关联：ADR-0022、ADR-0023、ADR-0026、`backend/evals/metrics.py`、`backend/app/services/rag.py`、`scripts/deploy_gate.py`

## 背景（Context）

基线 `f775fd92` 按 correctness 口径全量重评 51 条后，二次加权 Kappa = 0.3923，不升反降：

- 完全一致 28/51（54.9%）、±1 内 38/51（74.5%）、严重分歧（|Δ|≥3）5 条（9.8%）、bias +0.04；
- 5 条严重分歧中 4 条是结构性原因：2 条可答用例模型拒答（旧 prompt 过严）+ 人工误把「拒答=5」用于可答用例；1 条不可答案例模型答出了 KB 中真实存在的内容（标注错误）；1 条招呼语被裁判按「与标准答案一致」打成 1 分（judge rubric 缺“正确拒答=5”条款）；另 1 条为真裁决分歧；
- 双方分数高度集中在 4-5 档（裁判 42/51≥4、人工 38/51≥4），随机期望一致度 pe≈0.83，Kappa 对少量严重分歧极端敏感。55% 严格一致的现实下，0.6 的二次加权 Kappa 门槛不可达，用它做唯一闸门会把“总体高度一致、个别口径分歧”误判为不可信。

同时检索侧暴露观测缺口：hybrid 模式下关键词腿**无条件参与 RRF**（51/51 次运行均发生），但命中不记录来源腿，无法量化“关键词腿贡献”；且关键词腿是无 IDF 的双字滑窗计数、全量扫集合，弱查询词会制造噪声（Context Precision@5 仅 0.229，top1 相似度最低 0.037）；向量全被门控时仍会用关键词腿“保证有结果”，低置信场景不拦截。

## 决策（Decision）

### 1. 校准验收改为四指标 SLA（Kappa 降为观察指标）

由 `evals/metrics.py: calibration_from_pairs` 输出 `exact_rate / within1_rate / severe_rate / bias`，`calibration_sla` 做判定；样本 ≥10 对才判定：

- 严重分歧率（|Δ|≥3）≤ 5% —— 每条严重分歧必须逐条仲裁归因（标注错/裁判错/人工误用）；
- ±1 内一致率 ≥ 85%；
- 严格一致率 ≥ 60%；
- |bias|（LLM 均值 − 人工均值）≤ 0.3；
- Kappa 继续计算并展示（趋势/诊断），不参与闸门。

`evaluate_run_gate` 与 `scripts/deploy_gate --require-calibration` 均改用该口径；旧 calibration 数据（无四率字段）在重评任意一条后自动重算。

### 2. 检索观测：per-hit 来源腿

- `_rrf_merge` 为每条命中记录 `legs`（vector/keyword/双命中）与 `vector_rank`/`keyword_rank`；
- diag 记录 `keyword_leg_hits`（最终 top-k 中关键词腿贡献条数），检索诊断文案显示「关键词腿贡献 N 条」；
- trace `hits` 与评测结果 `hits` 均携带 legs 字段；评测行 metrics 增加 `keyword_leg_hits` 与 `low_confidence`。

### 3. 低置信门控：不再“永远有结果”

`rag` 配置 `low_confidence_rerank_min`（默认 0.45）：重排后 top1 低于阈值时返回空片段，由生成侧按拒答/引导处理；诊断文案显示「低置信…不提供片段」。消除“向量全被门控、关键词腿硬塞片段”的伪命中。

### 4. 关键词腿质量与 RRF 权重

- `_keyword_search` 改为 BM25-lite：jieba 分词（未安装回退双字滑窗）+ IDF 加权 + 标题命中 ×1.3；相似度按本查询最高分归一化；新增 `_QUERY_ALIASES` 家长口语别名扩展（退钱→退费、包过→保过班…，可持续补充）；
- `_rrf_merge` 支持分腿权重：`rrf_keyword_weight`（默认 0.5），关键词腿不再与向量腿同权；权重可配置并做 A/B。

### 5. 入库策略

- 分片入库时补文档标题前缀（`《标题》\n正文`），标题参与向量化与关键词检索（已含标题的块不重复加）；
- FAQ 短问句 + 紧随的“答：”块合并为同一分片（≤1600 字），避免问答语义被拆散；
- 注：以上影响分片文本 → **存量文档需要重建索引**才会生效；重建会重算 embedding（指纹/缓存机制不变）。

## 事故复盘与加固（2026-11-13，上线同日）

1. **工资结算负例泄露**：`child_code规章制度`（人事内部文档，含课时费结算条款）已改为家长不可见，但父集合里的旧分片不会被自动清理，且家长域检索只查「就绪+启用」不查可见性 → 两处修复：`usable_doc_ids(parent_visible=True)` 在父域过滤家长可见；`sync_parent_index` 同步时清理不再可见文档的分片。
2. **重建的破坏性顺序**：`index_document` 原实现先删旧向量再嵌入，上游 embedding 故障时把 16 篇父索引全部清空。改为**先嵌入、成功后再删除旧向量**——任何重建失败都不会降低当前可用性。
3. **家长索引内容版本**：新增 `PARENT_INDEX_VERSION`（当前 2），入库策略变化时递增并触发全量重建（不影响集合名/embedding 指纹）。
4. **上游 MaaS 网关 403**（`text-embedding-v4` 与 `qwen3-rerank` 同时 `Access to model denied`）：与本次代码变更无关，属账号/额度/模型授权问题，需运维在 MaaS 控制台排查；期间检索自动走关键词腿/本地兜底，且家长可见性过滤仍生效（不泄露）。受影响：父集合向量重建、重排、向量召回均降级。恢复后需重新执行父索引全量重建与检索 A/B。
5. **本地兜底不可用**：`models/Qwen3-Embedding-0.6B` 未就绪（local_embedding_ready=False），上游是唯一 embedding 通道——网关可用性目前是单点，建议后续将本地模型作为断网应急预案补齐。

**处置决策（2026-11-13，据负数复盘）**
- 「竞赛怎么准备？」用例标注无误，根因是 D3《备赛与集训安排》被停用（enabled=false）→ 已启用 D3（decided：enable）；
- 「老师工资结算」保持不可答负例（decided：keep negative），泄露已由可见性过滤与父索引清理修复，无需改标注；
- 「老师学历背景」标注与 gt 完整（retrieval rank1），无需改动，新生成 prompt 重跑后复评。

## 后果（Consequences）

- 重评后以四指标作为验收依据；Kappa 仅展示。当前 51 对数据在新口径下：±1=74.5%（未达标）、严重=9.8%（未达标）——先完成第 1 节“根因修复”（judge rubric 补条款随新基线一并做、修 2 条标注、2 条人工重评）再重跑基线。
- 低置信门控与 RRF 权重是**行为变更**：冻结集 hit@3 可能短期下降（低置信用例变为零结果），需用检索 A/B（不耗 LLM）确认后再进入答案评测；`low_confidence_rerank_min`/`rrf_keyword_weight` 均可配置回退。
- 标题前缀/FAQ 合并改变存量索引 → 重建后旧运行的检索指标与新运行不可直接对比（快照含 chunk 参数与集合指纹，仍可追溯）。
- 关键词腿升级后 jieba 为首选分词器；已加入镜像构建（`requirements-skills.txt`，免锁安装），运行时缺失会自动回退双字滑窗，行为不至于不可用。
