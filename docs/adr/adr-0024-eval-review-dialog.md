# ADR-0024：评测逐条复核改为弹窗连评（含检索视角）

- 状态：已采纳
- 日期：2026-11-12
- 关联：ADR-0022、CONTEXT.md、frontend/src/views/rag/RagEvalView.vue、frontend/src/views/rag/EvalResultReviewDialog.vue

## 背景（Context）

评测结果逐条「详情」原实现为行内展开，但展开行在模板中被渲染成整张表格之后的独立行（点击任意行的详情都出现在表底），人工复核体验差。同时人工打分入口只在表格行内联编辑，无法在查看裁判理由/回答的同时打分。另有认知混淆：纯检索运行（answer_eval off，如 dense/hybrid A/B）的逐条结果没有裁判与回答数据，详情看似「什么都没有」，用户误以为数据缺失。

## 决策（Decision）

**逐条详情合并为「复核弹窗」**（`EvalResultReviewDialog.vue`）：

1. 弹窗内完整展示：分层/关键度/可答性标签、检索命中 vs 标注相关、检索诊断、裁判五维与理由、生成回答与引用校验；底部 0-5 打分 + 上一条/保存并下一条/关闭。
2. 结果表提供「已复核 n/总数」进度与「只看未复核」筛选，连评导航遵循当前筛选清单；表格 query 列加分层/关键度/可答性标签。
3. **纯检索运行自动切换「检索视角」**：隐藏裁判、回答与打分区，顶部提示人工复核应选择开启答案评测的运行；表头状态说明该运行为纯检索 A/B。
4. 表格行内联打分移除，打分统一在弹窗内完成（保存后刷新运行指标以更新 Kappa）。

## 后果（Consequences）

- 人工复核路径清晰：基线运行（f775fd92，hybrid + answer_eval on）→ 弹窗连评 → Kappa 重算；纯检索运行只用于 A/B 对比，不再误导复核。
- 新增前端组件一个；`RagEvalView` 移除行内展开/行内打分相关状态与样式。
- 纯检索运行不会再出现「详情为空」的错误印象，但也不会产生人工分——这是有意为之（无裁判分可校准）。
