# Child Code 开发文档

> 本文档面向研发、实施与运维人员，按企业级系统落地文档规范组织，覆盖架构、权限、业务模块、后台管理、评测数据规格、用量成本与部署运维。所有内容以当前代码实现为准，随版本迭代持续更新。

## 文档定位

- **读者**：后端/前端研发、实施顾问、运维工程师、质量与合规同学
- **目标**：让新同学在一小时内跑通系统、理解模块边界、掌握鉴权与数据口径
- **原则**：单一事实来源（Single Source of Truth）、可追溯（版本/变更记录）、可执行（命令可直接复制）

## 文档地图

| 文档 | 内容 | 主要读者 |
| --- | --- | --- |
| 系统架构 | 技术栈、分层、目录结构、部署拓扑、关键设计 | 研发 / 运维 |
| AI 与 Agent 架构 | 模型接入、意图路由、Plan-and-Run 编排、工具与沙箱、记忆、多 Agent、RAG | 研发 |
| 权限体系 | 角色、权限键、职务预设、逐接口鉴权 | 研发 / 实施 |
| 业务模块 | 学员/班级/排课/反馈/报告/评估/习题等模块说明 | 研发 / 产品 |
| 后台管理（RAG） | 知识资产、检索路由、追踪、任务、会话、设置 | 研发 / 运维 |
| 评测数据规格 | 评测用例导入格式与合规要求（重点） | 研发 / 质量 |

## 推荐阅读顺序

1. 新同学：**系统架构 → AI 与 Agent 架构 → 权限体系 → 接口约定 → 业务模块**
2. 质量同学：**评测数据规格 → AI 与 Agent 架构 → 后台管理（RAG）→ 用量与成本**
3. 运维同学：**部署与运维 → 系统架构 → 权限体系**

## 文档规范

- **编号**：每个模块使用稳定英文 `slug`，路由形如 `/docs/{slug}`，便于外部系统与工单引用
- **术语**：统一使用「学员 / 教师 / 教务 / 管理员 / 家长」，避免同义词混用
- **变更**：接口或数据口径变更时，同步更新对应文档，并在 PR 描述中注明
- **示例**：命令与请求示例使用真实可执行的路径，占位符以 `<尖括号>` 标注
