## 关键业务规则

- **课时扣减**：每完成一节课按既定规则扣减课时，扣减需与考勤一致
- **催缴阈值**：课时低于阈值（默认 10 节）标记「爆红」并进入催缴名单；课时不足时提示续费
- **反馈闭环**：课后反馈保存后可推送家长，更新以最新版本为准
- **报告数据来源**：周报 > 课后反馈 > 日报，缺失数据在生成前提示补全
- **评估周期**：学员评估以近三个月反馈汇总生成，草稿必须经教师确认后才可发布
- **PPT 产物**：季度/年度总结与家长会 PPT 均为草稿态，审核确认后方为正式版

## 模块设计要点

### 学员与班级
学员可归属一个或多个班级，班级绑定科目与带教教师；学员列表突出课时余量与状态标签，催缴名单与列表共用同一数据源，避免口径不一致。

### 排课与考勤
排课详情承载到课与划课时操作，考勤结果直接驱动课时消耗，历史记录保留可追溯。

### 反馈 / 报告 / 评估
三者共享「AI 生成草稿 + 人工审核」的范式：生成仅产出草稿，发布与推送是独立动作，AI 调用统一走 LLM 上下文与用量记账。

### AI 习题与作业
教师按知识点生成习题并发布作业，学员按顺序或跳题作答后提交，教师在批改中心统一处理；提交事件触达家长通知。

### Agent 工作台（技术亮点）

Agent 是本系统最核心的智能能力，采用 **LangChain（ChatOpenAI / 原生 function calling）+ 自研 Plan-and-Run 编排**：

- 意图路由决定「闲聊 / 知识问答 / 业务查询 / PPT / 文档 / MCP / 混合」
- 规划器多轮调用工具（业务查询、只读 SQL、联网搜索、知识检索、Skill、MCP），带预算、去重与兜底
- 短期窗口 + 摘要 + 长期记忆 + 工作记忆共同支撑多轮连续任务
- Skill 在本地或远程沙箱（E2B / 百炼）执行，产物自动回传
- 全链路 span 观测与异步用量记账

> 说明：依赖中虽声明了 LangGraph，但当前**未使用** LangGraph，编排为自研循环。完整原理见「AI 与 Agent 架构」。

### 客户端
家长端聚焦课时余量、反馈、作业与订阅；学员端聚焦作业作答。客户端路由对 `parent/student` 隔离，管理端页面不可达。

## 与后台管理的关系

后台管理（RAG）为上层业务提供检索与 AI 能力支撑：知识资产供反馈/报告/客服等场景检索，检索路由与评测保障质量，用量与成本量化 AI 开销。详见「后台管理（RAG）」「用量与成本」两篇。
