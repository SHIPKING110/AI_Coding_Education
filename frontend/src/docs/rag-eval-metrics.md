# 评测指标解读与判读手册

> 适用页面：后台管理 → 评测（`/rag/eval`）、链路（`/rag/traces`）。本文解释每个指标「是什么、怎么算、多少算好、不达标先查哪里」，与 `rag-eval-spec`（导入规格）配套使用。所有指标均为**单次运行的统计口径**，冻结集（`split=frozen`）是最终判据。

## 一、指标分层总览

评测结果分四层，从上往下依次"可信"：

| 层 | 指标 | 回答什么问题 |
| --- | --- | --- |
| 检索层 | hit@1 / hit@3 / recall@5 / precision@5 / nDCG@5 / MRR | 该捞到的文档捞到了吗、排得对吗 |
| 答案层 | 忠实度 / 相关性 / 完整性 / 逻辑 / 正确性 / 关键词命中 | 回答得好不好 |
| 合规层 | 拒答率 / 引用覆盖率 / 无效引用率 / 无依据回答率 / 检索异常率 | 回答守不守规矩 |
| 可信层 | 裁判-人工 Kappa | 上面那些分到底可不可信 |

**判读顺序**：先看检索层（检索不对，答案层分数没有意义）→ 再看合规层红线 → 最后看答案层均分与 Kappa。**冻结集与关键用例切片永远优先于总体均值**——平均值会被大量普通用例稀释。

---

## 二、检索层指标

检索指标仅统计**可答用例**（`answerability=answerable` 且 `relevant` 非空）；不可答、未标注、检索异常单独计数、不进分母。off / on 分别对应重排关闭 / 开启。

| 指标 | 口径 | 合格参考线 | 优秀参考线 | 不达标先查什么 |
| --- | --- | --- | --- | --- |
| **hit@1** | 第一条命中相关文档的用例占比 | ≥ 0.70 | ≥ 0.85 | 首条是不是被大文档/FAQ 摘要抢占；考虑重排、标题实体加成、文档标题语义 |
| **hit@3** | 前三条至少命中一个相关文档的占比 | ≥ 0.90 | ≥ 0.95 | 仍是召回问题：top_k 是否过小、分块是否过碎、query 与标题是否对不上（补同义词/别名） |
| **recall@5** | 前五条覆盖相关文档的比例（多片段题看这个） | ≥ 0.90 | ≥ 0.95 | 答案散落多文档：加大 top_k、确认 parent-child 分块未丢片段 |
| **precision@5** | 前五条里相关文档占比 | ≥ 0.50 | ≥ 0.70 | 偏低通常是**正常现象**（top_k 是召回池），重点看是否伴随 no_hit/噪声引用 |
| **nDCG@5** | 考虑相关项排位的排序质量 | ≥ 0.80 | ≥ 0.90 | 相关项排得靠后：重排权重、相似度门控阈值（默认 `RAG_MIN_SIMILARITY=0.35`） |
| **MRR** | 首个相关命中的排名倒数（第 1 位=1.0，第 2 位=0.5…） | ≥ 0.75 | ≥ 0.85 | 与 hit@1 联动看：hit@1 高但 MRR 低说明"能捞到但排不稳" |
| **检索异常率** | 检索抛错的用例占比 | 必须 ≤ 0.1% | 0 | 看运行详情 error 条目的 trace 与 `retrieval_summary`；这是硬红线 |

> 经验基线（行舟家长客服集实测）：hit@1 0.73 / hit@3 0.93 / recall@5 0.94 / nDCG@5 0.85 / MRR 0.83，属于"可灰度"水平。**冻结集基线一旦确立，后续任何改动 hit@3 下降超过 2pp 即判闸门失败**。

## 三、答案层指标（0-5 分，LLM 裁判）

答案层需要运行表单开启「答案质量评测」（生成模型 + 裁判模型，两者必须不同）。每条用例的逐项分数可在结果表格「裁判分」列与「详情」展开中查看。

| 指标 | 口径 | 合格参考线 | 优秀参考线 | 不达标先查什么 |
| --- | --- | --- | --- | --- |
| **忠实度** | 回答是否只依据检索片段、无编造 | ≥ 4.2 | ≥ 4.5 | 低于 3 直接计入**无依据回答**（红线）；收紧生成 prompt"只依据片段、不足则答'文档未提供'" |
| **相关性** | 回答是否切题（而非答非所问） | ≥ 4.0 | ≥ 4.4 | 检查检索片段是否跑偏；生成 prompt 要求先复述问题要点 |
| **完整性** | 关键信息是否覆盖（对照 gt_answer） | ≥ 3.5 | ≥ 4.0 | 最常见短板。先分清：片段不全（recall 问题）还是生成过早收尾（prompt 要求按子点分条作答） |
| **逻辑** | 表述是否自洽、条理清晰 | ≥ 4.0 | ≥ 4.5 | 一般是格式问题，分条作答即可改善 |
| **正确性** | 与标准答案（gt_answer）事实是否一致 | ≥ 4.0 | ≥ 4.5 | 与忠实度交叉看：忠实但错误 = 片段本身过时/错误，要改知识库而不是改模型 |
| **关键词命中** | gt_keywords 在回答中出现的比例 | ≥ 0.85 | ≥ 0.95 | 详情页看「缺失关键词」，缺的是核心数字/时限就要修生成或补片段 |

> 行舟家长客服集实测：忠实度 4.53（强）/ 相关性 4.12（达标）/ 完整性 3.16（短板）——典型画像为"不乱说、基本对、答得不够全"。

## 四、合规层指标

| 指标 | 口径 | 红线 | 说明 |
| --- | --- | --- | --- |
| **拒答率（不可答集）** | 不可答用例中回答"文档未提供"的比例 | 越高越好 | 低于 0.8 说明对负例在硬答，先查生成 prompt 与相似度门控 |
| **引用覆盖率** | 非弃答回答中带 `[n]` 引用的比例 | ≥ 0.80 | 引用了才可追溯；客服场景对外输出建议保持高覆盖 |
| **无效引用率** | 引用编号超出片段范围的占比 | ≤ 5% | 偏高是生成幻觉信号，结合忠实度一起看 |
| **无依据回答率** | 非弃答且忠实度 < 3 的占比 | **必须 ≤ 5%** | 闸门硬红线，超限直接 fail |
| **检索异常率** | 同上节 | **必须 ≤ 0.1%** | 闸门硬红线 |

## 五、裁判可信度（Kappa）

LLM 裁判打分是"参考值"，只有与人工高度一致才能作为上线依据。

- **人工复核**：结果详情每条可打 0-5 分（「评分」按钮），与裁判的 correctness 配对；
- **Cohen's Kappa**：≥ 10 对才计算；**< 0.6 判闸门 fail**（0.6-0.8 为 substantial，≥ 0.8 为 almost perfect）；
- 实操：挑 **completeness ≤ 3** 的用例优先复核（分歧最可能出在"答得全不全"上），10-15 条即可出稳定 Kappa；
- Kappa 不达标时，先校准裁判 prompt（给 gt_answer、要求引用片段原文），而不是怀疑人工标注。

## 六、验收闸门（deploy_gate / 前端横幅）

同评测集「当前运行 vs 上一次完成运行」自动比对，前端结果页横幅与 CLI `scripts/deploy_gate` 是同一份判据：

| 判据 | 阈值 | 说明 |
| --- | --- | --- |
| 冻结集 hit@3 回退 | ≤ 2pp | 冻结集是最终红线 |
| 关键用例（critical）hit@3 回退 | ≤ 2pp | 退费/收费/安全/年龄门槛等高风险切片 |
| 无依据回答率 | ≤ 5% | 防编造 |
| 检索异常率 | ≤ 0.1% | 稳定性 |
| 裁判-人工 Kappa | ≥ 0.6（≥10 对） | 裁判可信度 |

- 前端横幅：`pass`（可发布）/ `fail`（拦截，列出原因）/ `skip`（无历史基线或样本不足）；
- CLI：`python -m scripts.deploy_gate --set-id <uuid>`，exit 0 放行 / 1 拦截 / 2 基线缺失；
- 发布命令：`GATE_SET_NAME="行舟-家长客服回归集" make release`。

## 七、运行对比面板（跨运行 A/B）

运行详情头部「与运行对比…」可选同评测集另一条已完成运行作基准（如 dense 基线 vs hybrid）：

- 11 项差值并排：hit@3/hit@1/MRR/recall@5/nDCG@5、冻结/关键切片、忠实度/完整性、无依据率、Kappa；
- **绿 = 优于基准，红 = 劣于基准**；无依据率方向反转（越低越绿）；
- 缺数据项显示「样本不足」，不参与判断。

典型判读：hybrid 相对 dense，hit@1 +2pp 以上且冻结 hit@3 不降 → 可灰度；hit@1 提升但无依据率上升 → 先查门控与裁判分歧，不要直接上线。

## 八、Bad Case 定位决策树

发现某条用例分数低时，按顺序排查：

1. **ranked 里有没有相关文档？** 没有 → 召回问题：补别名/同义词、检查分块、加大 top_k；
2. **有但排得靠后？** → 排序问题：开重排、调 `RAG_MIN_SIMILARITY`、标题语义；
3. **检索对但忠实度低？** → 生成问题：收紧"只依据片段"prompt，检查片段是否被截断；
4. **忠实度高但完整性低？** → 覆盖问题：分条作答 prompt、top_k 加一档、确认多片段题 recall@5；
5. **以上都对但分数低？** → 裁判问题：人工复核 3-5 条看 Kappa，校准裁判 prompt 或改 gt_answer。

> 线上 Bad Case 的来源：链路页（`/rag/traces`）按「反馈 = 踩」筛选 → 抽屉「加入评测集」（可选冻结/关键度）→ 下次评测自动回归。
