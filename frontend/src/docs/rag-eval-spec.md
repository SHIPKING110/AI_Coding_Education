# 评测数据规格与合规说明

> 适用页面：后台管理 → 评测（`/rag/eval`）。本规格描述外部评测用例的批量导入格式、字段语义、校验规则与合规要求。系统仅做结构校验，不做语义校验；导入前请自行完成数据清洗与脱敏。

## 一、评测工作流

```text
建立评测集 → 导入/生成用例 → 选择检索开关与生成/评测模型 → 运行 → 查看指标与对比 → 复核 Bad Case → 调参回归
```

1. **建集**：在评测页新建或选择评测集
2. **备用例**：批量导入（本规格）或从文档分片生成候选用例
3. **运行**：分别以检索关闭（off）与开启（on）运行；勾选答案质量评测时，分别选择生成模型与评测模型
4. **看指标**：hit@k、MRR、recall、答案关键词命中、裁判评分等
5. **复核**：对未命中与低分用例标注 Bad Case 类型，沉淀为回归集
6. **回归**：调整检索参数或提示词后重跑，对比前后指标

## 二、字段定义

| 字段 | 必填 | 类型 | 说明 |
| --- | --- | --- | --- |
| `query` | 是 | string | 用户问题（评测输入） |
| `relevant` | 否 | string[] / string | 应命中文档标题，用于 hit@k / MRR / recall |
| `gt_answer` | 否 | string | 标准答案，用于答案质量评测 |
| `gt_keywords` | 否 | string[] / string | 标准答案关键词，用于关键词命中率 |
| `query_type` | 否 | enum | `fact`（默认）/ `compare` / `howto` / `policy` |
| `difficulty` | 否 | enum | `easy` / `normal`（默认）/ `hard` |
| `notes` | 否 | string | 备注、来源或预期 Bad Case 类型 |
| `source` | 否 | string | 来源标识，默认 `import`；建议填批次号/脚本名 |

> 若 `relevant` 与知识库文档标题不一致，不会报错，但该用例 hit@k 恒为 0，评测结果会失真。导入前务必核对标题。

### 2.1 生成模型与评测模型

勾选「答案质量评测（LLM 裁判）」后，需要分别选择：

| 角色 | 作用 | 建议 |
| --- | --- | --- |
| 生成模型 | 基于检索片段生成回答，用于关键词命中与裁判评分 | 与线上客服/教学实际使用的模型保持一致 |
| 评测模型 | 对回答的忠实度、相关性、完整性、表达、逻辑打分 | 选择不同厂商或不同模型，降低同源偏好；temperature=0 |

- 两个模型必须不同（配置 ID 与模型名都不能相同），前端与后端都会校验
- 模型来自当前评测集 owner 在「设置 → 模型配置」中已配置的模型
- 只跑检索指标（hit@k / MRR / recall）时不会调用 LLM，模型选择不生效
- 每次运行会快照生成/评测模型名，历史记录可在运行表中追溯

## 三、支持格式

评测页支持**多文件批量导入**：可一次选择多个 JSONL / JSON / CSV 文件，也可直接拖拽文件到导入区，或粘贴文本。系统会先解析并展示预览（有效条数、解析失败行号），确认后再入库。

### JSONL（推荐）
每行一个 JSON 对象，适合流式与大文件，解析失败的行会被报告。

```json
{"query":"如何办理退费？","relevant":["退费政策文档"],"gt_answer":"请到前台提交退费申请，3-5个工作日到账。","gt_keywords":["前台","退费申请","3-5个工作日"],"query_type":"policy","difficulty":"normal","notes":"政策类标准用例","source":"batch-2026-06"}
{"query":"Python 课每次消耗几课时？","relevant":["课时包说明"],"query_type":"fact","difficulty":"easy"}
```

### JSON 数组
整体为数组，元素结构同上。

```json
[
  {"query":"如何办理退费？","relevant":["退费政策文档"],"query_type":"policy"},
  {"query":"Python 课每次消耗几课时？","relevant":["课时包说明"],"query_type":"fact"}
]
```

### CSV
首行表头，逗号分隔；文本含逗号用双引号包裹；多值字段用 `;` 分隔。

```text
query,relevant,gt_answer,gt_keywords,query_type,difficulty,notes,source
"如何办理退费？","退费政策文档","请到前台提交退费申请","前台;退费申请;3-5个工作日","policy","normal","政策类标准用例","batch-2026-06"
```

## 四、校验规则

1. `query` 必须非空；空行自动跳过
2. `relevant` 中不存在的标题不报错，但会导致命中类指标失真
3. 单次导入上限 **500 条**，超出请分批；支持多文件合并计数
4. 导入**只追加、不覆盖**；默认按 `query`（忽略大小写与首尾空格）**跳过重复**，可在导入区关闭该开关
5. `query_type` / `difficulty` 非法值按默认值处理
6. 导入结果会给出成功/跳过/失败计数；解析失败与字段校验失败会按行号列出，修正后可重导
7. **批次命名（`source`）只是来源标记**，不会改变评测逻辑；同一评测集内所有用例会一起参与运行。不同批次名不会自动分组或隔离
8. 关闭「跳过重复 query」时，重复用例会重复计入指标；建议保持默认开启，或导入前自行去重

## 五、合规与安全要求（导入前必读）

1. **脱敏**：`query`、`gt_answer`、`notes` 不得含真实学员姓名、手机号、身份证号、家长联系方式、订单号、教师隐私；使用占位符（如「学员A」「教师B」）或哈希
2. **版权**：`relevant` 必须是本系统已接入的知识资产，不得导入第三方受版权保护的全文作为标准答案
3. **最小必要**：仅导入评测所需字段，不要整表导入业务库原始记录
4. **审计**：每次导入写入审计日志（操作者、数量、时间），请保留清洗脚本与原始数据以便追溯
5. **可回滚**：导入前保留原始文件与批次号，异常时按 `source` 定位并清理

## 六、指标口径

| 指标 | 含义 | 依赖字段 |
| --- | --- | --- |
| hit@k | 前 k 条召回是否命中任一相关文档 | `relevant` |
| MRR | 首个相关文档排名的倒数均值 | `relevant` |
| recall | 相关文档被召回的比例 | `relevant` |
| 关键词命中 | 回答覆盖标准答案关键词的比例 | `gt_keywords` |
| 裁判评分 | LLM 按维度对答案打分 | `gt_answer` |

> 未提供 `relevant` 的用例不参与命中类指标；未提供 `gt_keywords` / `gt_answer` 的用例不参与对应质量指标。

## 七、评测成本

评测运行产生的 LLM 调用（生成回答、裁判打分）归因到「用量与成本」模块 `rag_eval`，可在用量看板按模块筛选与对账。答案质量评测每个用例至少产生 **2 次** LLM 调用（生成 + 裁判），且两个模型分别按各自价格计费；大规模评测前建议先用小样本估算单次成本。

## 八、常见问题

- **导入成功但 hit@k 全为 0**：多为 `relevant` 标题与知识库标题不一致，核对后重导
- **CSV 解析错列**：文本含逗号未加双引号，或多值字段未用 `;` 分隔
- **超出上限**：单批 > 500 条被拒，请拆分批次并保留 `source`
- **评测成本偏高**：减少裁判调用或缩小样本，关注 `rag_eval` 模块耗费
- **批次命名不同有影响吗**：没有功能影响；`source` 只是来源标记，所有批次仍一起参与评测。重复 query 默认会被跳过
- **多文件导入顺序**：按选择/拖拽顺序合并解析；同一批次内重复 query 只保留第一条
- **提示“模型配置不属于评测运行 owner”**：生成/评测模型必须属于评测集 `owner_id`（未填时为当前账号），请切换到对应账号配置模型，或清空 `owner_id`
- **提示“生成模型与评测模型不能使用同一个模型”**：请选择不同模型；即使两个配置指向同一模型名也会被拒绝
