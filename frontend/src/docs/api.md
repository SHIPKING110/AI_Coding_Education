# 接口约定

## 基础约定

- **Base URL**：`/api`（前端 axios 已配置；开发环境由 Vite 代理到后端）
- **协议**：HTTP + JSON，字符集 UTF-8
- **时间**：ISO 8601 字符串，前端统一格式化展示
- **金额**：以「分」或明确单位返回，展示层转换
- **文件**：上传使用 `multipart/form-data`，字段名以各接口为准

## 鉴权

- 登录成功返回 `access_token` 与 `refresh_token`，前端存于 `localStorage`
- 请求头携带 `Authorization: Bearer <access_token>`
- **自动续期**：收到 `401` 时前端用 refresh token 换取新令牌并重放一次原请求；刷新失败则清理登录态跳转登录
- 后端按角色与权限键二次校验，前端守卫仅控制体验

```bash
curl -H "Authorization: Bearer <access_token>" http://127.0.0.1:8000/api/<resource>
```

## 分页

- 查询参数：`page`（默认 1）、`page_size`（默认 20，受上限约束）
- 响应：列表数据 + `total`，前端据此计算总页数
- 大列表优先使用服务端筛选与排序，避免整表拉取

## 错误结构

错误统一返回 `detail` 字段，前端优先展示可读文案：

```json
{ "detail": "缺少权限：finance_view" }
```

| 状态码 | 含义 | 处理建议 |
| --- | --- | --- |
| 400 | 参数非法/业务校验失败 | 按 `detail` 修正入参 |
| 401 | 未认证或令牌失效 | 自动刷新，失败则重新登录 |
| 403 | 无权限 | 检查角色与权限键 |
| 404 | 资源不存在 | 核对路径/ID |
| 409 | 冲突（重复/状态不允许） | 刷新后重试 |
| 422 | 结构校验失败 | 按字段提示修正 |
| 500 | 服务异常 | 查看后端日志 |

## 通用约定

- **幂等**：写操作按业务设计保证幂等（如用量记账、预算告警）
- **限流**：敏感接口按用户/来源限流，超限返回 `429`
- **审计**：高影响操作写入审计日志（操作者、对象、时间、变更）
- **一致性**：删除/重索引等联动操作在事务边界内完成，失败回滚

## 接口分层建议

1. 前端在 `src/api/` 按域封装（如 `ragAdmin.ts`、`usage.ts`），统一出入参类型
2. 页面只调用封装函数，不直接拼接 URL
3. 新增接口同步更新本文档与 Swagger（`/api/docs`）

## 调试入口

- Swagger：`http://127.0.0.1:8000/api/docs`
- 健康检查：`http://127.0.0.1:8000/api/health`
